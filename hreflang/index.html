Hreflang: Why International SEO Implementations Fail

Hreflang is easy to add and fails quietly. It works only when every page in a cluster confirms every other page and agrees with Google’s view of canonicals and indexing. Google’s documentation, staff statements and large audits show where that agreement breaks.

Key takeaways

  • Hreflang does not make pages rank. It tells Google which URL to show from a set of equivalent pages that already compete for a query. In John Mueller’s words, “There is no bonus for hreflang.”
  • A pair of pages counts only if both are indexed, both are canonical, both name each other and both use valid codes. Google ignores a broken pair without reporting it.
  • The number of annotations grows with the square of the number of locales. In a worked example, 10,000 pages translated into 20 locales need 4 million annotations.
  • Large audits find issues on most sites that use hreflang. The most common one, a missing x-default, is optional in Google’s documentation. Problems that break pairs, such as missing return links, each affect between 2.5% and 17% of domains in the largest audit.
  • Versions in the same language for different countries are often folded into one canonical. Hreflang may still show the local URL in results, but Search Console reports the canonical, so a working setup can look broken.

Routing, not ranking

Hreflang looks like a meta tag. It behaves more like a shared database. Every page in a set of language or regional versions lists the address of every other version, and each of those pages has to list it back. In 2018 John Mueller of Google wrote: “TBH hreflang is one of the most complex aspects of SEO (if not the most complex one).” He added: “Feels as easy as a meta-tag, but it gets really hard quickly.” [1]

The job itself is narrow. Google’s documentation puts it in one sentence: given a set of equivalent pages, “Google Search returns the appropriate result for the user, according to their browser settings.” Hreflang also does not tell Google what language a page is in. Google says it uses neither hreflang nor the lang attribute for that, but “the visible content of your page”. [2][3] A German page annotated as English is still a German page.

Nor does it add ranking strength. Mueller wrote in 2022: “There is no bonus for hreflang, it's only about showing the most-fitting page in search for users in a specific country / language.” [4] Hreflang works on pages that are already eligible to appear. If the German page ranks for a query in Austria, hreflang can swap in the Austrian version. If no version ranks, there is nothing to swap. Fixing hreflang fixes the wrong market’s URL appearing in results. It does not fix weak local content or a market where the site does not rank at all.

The same reply set a practical test. Mueller suggested checking analytics for search traffic that lands on the wrong country or language version: “If you don't find a big mismatch there, most likely you don't need to do a lot (or anything) for hreflang.” He expected most problems in “same-language / different-country situations” and on home pages, where brand names are not localized. [4] Other search engines weigh hreflang differently. Fabrice Canel of Microsoft wrote in 2020 that “hreflang is indeed a far weaker signal than content-language at Bing.” [5]

A cluster is an agreement between pages

Google reads hreflang in three places: link elements in the HTML head, HTTP headers and XML sitemaps. “The three methods are equivalent from Google's perspective.” The rules are the same in all three. “Each language version must list itself as well as all other language versions.” Alternate URLs must be fully qualified. And the rule behind most failures: “If two pages don't both point to each other, the tags will be ignored.” [2]

The return-link rule is a safeguard. It exists so that “someone on another site can't arbitrarily create a tag naming itself as an alternative version” of a page. Its consequence is that hreflang is evaluated pair by pair. A cluster of ten versions contains 45 pairs. If one page stops linking back, the pairs that include it fail, while “Google will still process the ones that point to each other”. [2] Nothing breaks loudly. Part of the cluster simply stops working.

Agreement between the annotations is not enough. Each page also has to agree with what Google knows about it from other signals.

Both pages have to be indexed. Gary Illyes of Google, who said he had worked on Google’s hreflang support, explained in 2020 that the annotations “are picked up once all pages that you linked together with them” are “crawled and (re)indexed”. [6] Mueller repeated the point in 2025: “hreflang doesn't guarantee indexing.” [7] Indexing is a separate decision, made on separate grounds, as the crawlability vs. indexability study explains. By the same logic, a page that redirects, returns an error or carries noindex cannot complete a pair.

Both pages have to be canonical. In 2015 Mueller warned: “If the specified canonical URL is not a part of the hreflang pairs, then the hreflang markup will be ignored.” A canonical tag that points across languages does more damage. His example: “don't specify the ‘de’ page as the canonical for the ‘en’ version, otherwise we won't index the ‘en’ version”. [8] Google’s canonical documentation keeps the rule: “If you're using hreflang elements, make sure to specify a canonical page in the same language, or the best possible substitute language if a canonical page doesn't exist for the same language.” [9]

The codes have to be valid. Google supports only ISO 639-1 language codes and ISO 3166-1 Alpha 2 region codes. A language can stand alone; a region cannot. “You can't specify the country code by itself.” Codes outside those standards, “such as es-419, aren't supported.” Reserved codes are partly ignored: “using EU, UN, or UK in hreflang annotations doesn't have an effect on Google Search.” [2] An annotation of en-uk therefore counts only as English, not as British English. The region code for the United Kingdom is gb.

The arithmetic of scale

Because every version lists every version, the number of annotations grows with the square of the number of locales. Figure 2 is a worked example: a site of 10,000 pages translated into more and more locales.

Two languages need 40,000 annotations. Ten locales need a million. Twenty need four million, and 3.8 million of those are claims about another page that the other page has to confirm. Adding a 21st locale means editing the annotations on all 200,000 existing pages, not just publishing 10,000 new ones.

Sitemaps have their own limits. “All formats limit a single sitemap to 50MB (uncompressed) or 50,000 URLs.” [12] With 20 locales, each sitemap entry carries 20 alternate links. With URLs of ordinary length, an entry runs to about 2.3 KB, so the size limit arrives at roughly 21,000 entries instead of 50,000. The 200,000 URLs need about ten sitemap files, not four.

Crawling adds a delay. Pairs are confirmed only after both pages are crawled and indexed, so when one locale’s URLs change, every page that names them has to be updated and crawled again before the cluster agrees. On a site that already struggles to get pages crawled, for the reasons covered in the crawl budget study, that delay can be long.

Organisation is the larger problem. Country sites are often run by separate teams, on separate CMS instances or with separate translation workflows. Mueller called linking all versions of all pages “the clean approach, however, sometimes it's just a ton of work”. He also pointed to the way out. “Hreflang is on a per-page basis, so the beauty (and curse) is that you can pick & choose,” and “Nothing breaks if you set up hreflang for 2 versions and have 4 unrelated versions.” [4] Annotating only the home pages, or only the same-language markets that get confused, is a legitimate setup.

What audits find

Three large hreflang audits have been published, all by companies that sell auditing tools or services. Ahrefs looked at 374,756 domains that used hreflang and found that “67% of them have at least one issue.” [13] Dan Taylor of SALT.agency analysed 18,786 sites with hreflang in the HTML head, from a list supplied by NerdyData, and found conflicting directives on 31.02% of them. [14] A 2017 Semrush study of 20,000 multilingual sites reported that “75% of websites have at least one hreflang implementation mistake.” [15]

The headline numbers cannot be compared: the studies define issues differently, Ahrefs publishes no methodology, and none samples the web at random. The detail is more useful, because it separates common problems from serious ones.

Figure 3. Hreflang issues found by Ahrefs on 374,756 domains that used hreflang, grouped by how Google’s documentation treats each one. Vendor study, published 2023, no methodology published; grouping by the author. Sources: [2][13].

The most common issue in the Ahrefs data is not an error. 56.3% of domains had pages missing x-default, and Taylor found 47.95% of sites without it. [13][14] Google describes x-default as the value “used when no other language/region matches the user's browser setting”, designed “for language selector pages”, and only asks sites to consider a fallback page. [2] Missing self-references come next, at 18% of domains in Ahrefs’ data and 16.04% of sites in Taylor’s. [13][14] Here the sources disagree. Google says each version “must list itself” [2], while the Ahrefs study calls self-referencing tags “really more like a best practice and not actually required”. [13]

The problems that break pairs are less common, but still frequent. In Ahrefs’ data, 16.9% of domains had hreflang pointing to redirected or broken pages, 15.3% had pages missing return tags, 8% pointed hreflang at non-canonical URLs and 4.6% used incorrect values. [13] Taylor found invalid language codes on 8.91% of sites and invalid region codes on 1.6%. [14] Each figure counts sites with at least one affected page, so it says nothing about how much of each site is affected. A single redirected URL and a fully broken cluster count the same.

Adoption puts the figures in proportion. The HTTP Archive’s 2024 Web Almanac found hreflang on 10% of desktop and 9% of mobile websites in its crawl. [16] It is a minority technology, and most of the sites that use it get some part of it wrong.

The same-language problem

Translation is not duplication. “Localized versions of a page are only considered duplicates if the main content of the page remains untranslated.” [2] A French page and a German page are different documents, and duplication would not be a penalty in any case, as the duplicate content penalty myth explains.

Versions in one language for different countries are another matter. British, Irish and Australian pages often differ only in currency, spelling or delivery details. Google’s systems see near-identical pages and may keep one. In 2025 a site owner saw Belgian French pages appearing in France. Mueller replied that if the versions “are the same (eg fr-fr, fr-be), it's common that one is chosen as canonical (they're the same).” Then: “Often hreflang will still swap out the URL, but reporting will be on the canonical URL.” [7]

Gary Illyes described the mechanism in 2026. When Google picks a canonical, the other URLs in the duplicate cluster “may become so called alternate names”, which can appear in results when a query calls for them. Hreflang alternates are among them: “they're not in fact indexed in the proper sense.” [17] Google’s canonical documentation adds that “for canonicalization purposes Google prefers URLs that are part of hreflang clusters.” [9]

This produces an easily misread symptom. A regional page can show as a duplicate in Search Console while its URL appears in that country’s results. Treated as a failure, it invites new canonicals, noindex or removing hreflang, any of which can break a setup that was working. Mueller’s “they're the same” also suggests what decides the outcome: regional versions that differ only in a currency symbol give Google little reason to index them separately.

Silent failures

Most hreflang failures produce no error. Google ignores what it cannot use.

Redirects by location hide versions. According to Google, Googlebot “usually originates from the USA” and crawls “without setting Accept-Language in the request header”. [3] A site that redirects visitors by IP address or browser language may show Googlebot only one version. Google advises against such redirects because they “could prevent users (and search engines) from viewing all the versions of your site,” and suggests “adding hyperlinks to other language versions of a page.” [3] A language switcher built from real links is a discovery path as well as a usability feature, for the reasons set out in the internal linking study.

A broken head hides the tags. “If you use an invalid element in the <head> element, Google ignores any elements that appear after the invalid element.” Google names img and iframe as common examples. [10] Hreflang links placed after one are never read, and Mueller noted in 2016 that “if we can't find the hreflang markup at all, we won't flag it as an error”. [18] The 2024 Web Almanac found invalid elements in the head of 10.6% of desktop and 10.9% of mobile pages. [16]

Conflicting sources cancel each other. Google combines hreflang from the HTML and from sitemaps. When the two assign the same language and country to different pages, Mueller said in 2020, “we would see this doesn't work and we would probably drop that pair.” [11] Sites that generate annotations in two systems, a template and a sitemap plugin, carry this risk on every release.

Nothing reports it any more. Search Console’s International Targeting report, launched in 2014, was used “to monitor your hreflang errors”. [19] Google removed it on September 22, 2022. [20] The deprecation notice says that country targeting “was determined to have little value for the ecosystem” and that Google “will continue to support and use hreflang tags”. It points to the hreflang documentation, not to a replacement report. [21] Since then, hreflang errors have surfaced as the wrong URL in the wrong market, or in a crawl.

The cost shows up in results. When Clarks moved its Spanish, French, German and Italian country domains into folders on clarks.eu in 2020, SISTRIX found hreflang tags that did not point to canonical URLs, URLs missing return links and no x-default. It also found that 61% of keywords ranked with URLs belonging to other markets, rising to 68% in France. [22] SISTRIX connected the two without testing the link, and the move bundled many other changes, as the migration study describes.

Auditing hreflang as a system

On the large sites I have audited, up to around two million URLs, hreflang problems rarely sit in the tags themselves. They sit between systems: the template that prints the annotations, the sitemap generator, the canonical logic, the redirect rules and the translation workflow that decides when a page exists in each language. Each part can be correct on its own and wrong in combination.

An audit that reflects this treats the annotations as a graph. A crawl of every locale collects each page’s claims and checks every target: its status code, its canonical, its indexability and whether it links back. Annotations in the HTML are compared with those in the sitemaps. Results are grouped by template, because a broken rule repeats on every page that uses it. The last step compares the graph with search data: which URL Google shows in each market for queries where the wrong version could appear. Mueller’s advice runs the same way: “When checking, focus on the most likely mistakes first,” starting with same-language markets and home page traffic. [4]

That last step decides what the findings mean, because the tags are only a means. A clean graph with the wrong URLs in results points to canonicalization or content. A messy graph with the right URLs in results may not need much work at all.

Conclusion

Hreflang implementations fail because hreflang is an agreement, not a tag. Every page in a cluster has to confirm every other page, and each of them has to be the indexed, canonical, reachable URL that Google keeps. A page that redirects, names a canonical in another language or drops a return link breaks every pair it belongs to, and Google discards those pairs without saying so. The number of claims grows with the square of the number of locales, and the systems that produce them are often owned by different teams.

The evidence also limits what hreflang can do. It routes users to the right version among pages that already rank. It adds no ranking strength. It cannot stop near-identical regional pages from being folded into one canonical, although it may still show the local URL. The useful measure of a hreflang setup is not a clean audit report. It is whether each market sees its own URL in search.
